# 对战 AI 优化设计

用户范围：全面优化电脑决策与工程质量，采用成熟方法；继续使用目前可对战的20名角色和已有技能效果。上一次V1.9资源更新及工作区其他改动必须保留。

采用 Utility AI：观察公开局面 → 枚举可行操作 → 评估收益与代价 → 经共享规则入口执行 → 检查执行结果并重新观察。该模式依据 Dave Mark / Kevin Dill 的 GDC 讲座与 Game AI Pro 第9章，而具体收益必须来自本游戏的真实规则与测试，不能宣称启发式评分是最优策略。

## 方案与取舍

- 继续加固定 if/else 阶段：改动小，但抽牌、回复AP后的操作仍容易遗漏，不采用。
- Utility AI：可解释、可测试，适合当前小型回合制游戏，采用。
- MCTS/强化学习：需可复制的纯模拟器、随机数与训练评估基础，当前投入超出本次必要范围。

## 约束

- 保持 AiService.executeTurn(state, player) 与 REST 接口兼容。
- AI只读取己方手牌、公开角色/状态/弃牌、敌方手牌数量、牌库剩余数量；不读取敌方手牌身份或牌堆顺序来决策。
- 动作经游戏规则入口执行，不能绕过回合、玩家存活、状态、AP与skipAction限制。
- 每次成功动作后重新枚举；失败动作不能无穷重试；存在明确预算；游戏结束立即停止。
- 攻击按有效伤害、护甲/格挡/守护、退场/淘汰收益与反击风险考虑。参数完整且失败可观察。
- 考虑抽牌、补充、部署/替换、回复与AP恢复、已实现且有价值的道具、策略、角色技能；不把没有消费者的反应buff存根当作有效收益。
- 修复必要规则边界：失败技能不得预先扣AP；策略处理器改变手牌后仍按uid正确移除出牌，不能丢失/复制卡牌。
- 普通无牌攻击是当前游戏已有功能，AI可以合理保留等价攻击牌，不为测试强迫浪费卡牌。
- 不新增大型游戏AI框架，不接入语言模型服务，不改变V1.9尚未实现的技能。

## 验证

Jest真实服务场景覆盖：缺少攻击者、跳过行动/错回合、状态限制、守护/免疫、抽牌后再用牌、回复AP后继续进攻、避免重复治疗、合法策略目标、隐藏信息置换不改变决策、失败终止、反击退场、游戏结束、uid守恒。构建与完整测试通过；运行可重复的多局烟测，报告结果与局限。
